# 06 — Frontend (app + Android)

Two front ends, by purpose:

| Part | Tech | Where | Why |
| --- | --- | --- | --- |
| Public site (SEO) | Jinja2 server-rendered by the backend, small vanilla JS islands | `backend/cendekiara/web/` | crawlable HTML, fast, CDN cached (`09-seo-and-sites.md`) |
| App behind login (student + admin) | React 18 + Vite + TypeScript SPA | `frontend/`, served at `/app/` | rich exam UI, one codebase for web and Android |
| Android | Capacitor wrapping `frontend/dist` | `frontend/android/` | Play Store app without a second codebase |

## Stack (app)

- React 18, Vite, TypeScript `strict`, React Router, TanStack Query (server
  state), `react-i18next` (`src/i18n/id.json`, `en.json`).
- Styling: CSS Modules + CSS variables for theme tokens (`src/styles/tokens.css`).
  No CSS framework. Mobile-first; every screen works at 360 px width.
- Math: KaTeX (`trust: false`), loaded only when a text contains a formula.
- Auth: Firebase Auth JS SDK on web; `@capacitor-firebase/authentication`
  on Android. Both give an ID token → `Authorization: Bearer`.
- Tests: Vitest + Testing Library. Lint: ESLint (typescript-eslint,
  react-hooks). Format: Prettier (2 spaces, single quotes, no semicolons).

## Rules

1. Talk to the backend only via `src/api/client.ts`:
   `call<Name>(args)` → `POST /api/commands/{name}`, `get<Name>(args)` for
   readonly. Types come from `src/api/types.gen.ts` (generated by
   `make schema`); never hand-write API types.
2. No Firestore SDK, no model API, no secrets in the frontend. Firebase web
   config (public by design) comes from `src/config.ts`, set at build time
   via `VITE_*` env vars.
3. One folder per feature: `src/features/<feature>/` (pages, components,
   hooks). Exam layouts in `src/exam/layouts/<layout>/`, question types in
   `src/qtypes/<type>/` (plugins, see `04-exams.md`).
4. All text via i18n keys in both `id` and `en`. Interface language = the
   user's `lang`; question language follows the exam (`contentLang`).
5. `localStorage` only through `src/lib/storage.ts` (try/catch wrapped), for
   per-device conveniences (e.g. stats panel open). Never answers or tokens
   beyond what Firebase Auth stores itself.
6. Icons: one SVG sprite (Lucide style, ISC). Icon-only buttons need
   `aria-label`.
7. Capacitor: the API base URL is absolute in the Android build
   (`VITE_API_BASE=https://cendekiara.com`); CORS on the backend allows the
   Capacitor origin only for `/api/commands/*`. Use plain web APIs; native
   plugins only behind `src/lib/native/*` with a web fallback.

## Shared UI pieces

- **QuestionCard** (`src/features/card/`): question + "Cek jawaban"
  (server-graded), explanation, family method, stats (toggle remembered per
  device), notes mode (transparent canvas: 3 pen colours, eraser, clear,
  palm rejection after stylus use, not saved), Like/Save/Share/Report.
  Used in Study, home and the question page. The public article/question
  pages render a static version server-side and hydrate it with the same
  logic in a small island script.
- **Exam room**: `useAttempt` + the layout plugin.
- **Admin** (`/app/admin/`): overview, question bank, AI generate, packages,
  articles, reports, item stats. Visible only if `user.me` says admin; the
  server checks anyway.
